# AGENTS.md

Ведёшь агент? Этот файл — руководство по работе с кодом в этом репозитории.

## Обязательное правило

При **каждом** изменении кода (HTML/CSS/JS) актуализировать документы: `AGENTS.md`, `analyse.md`, `README.md` — синхронно с правками, без отставания в следующих итерациях.

## Обзор проекта

Статическое мультистраничное веб-приложение (vanilla HTML/CSS/JS, без сборки): каталог «Онлайн магазин» — категории → позиции (товары/услуги), корзина и заказы со статусами (`new → processing → done`). Все данные на стороне клиента: `localStorage` + зеркало заказов в `window.name`.

Корень репозитория содержит только документы; код разложен по подкаталогам — один каталог на страницу, общие модули в `common/`. Точка входа — `categories/index.html`.

## Структура

| Путь | Назначение |
|---|---|
| `categories/index.html` + `js/script.js` | Страница категорий (CRUD) |
| `catalog/index.html?category=...` + `js/main.js` | Каталог категории: CRUD позиций, фильтр по типу, «Заказать» (корзина → 350 мс → checkout) |
| `checkout/index.html` + `js/main.js` | Корзина (stepper 1–99, удаление) + форма покупателя |
| `orders/index.html` + `js/orders.js` | Список заказов: поиск, фильтр по статусу, сводка |
| `orders/order-detail.html?id=...` + `js/order-detail.js` | Детали заказа: состав позиций, таймлайн и смена статуса (только вперёд) |
| `common/js/data.js` | Модель каталога: CRUD категорий/позиций, валидация, seed-данные |
| `common/js/cart.js` | Корзина (`cart_v1`) |
| `common/js/storage.js` | Заказы: чтение/запись через `window.name` (`orders::`) + зеркало в `localStorage[catalog_orders]`; правила использования — см. «Примечания» ниже |
| `common/js/utils.js` | Общие утилиты: `escapeHtml`/`escapeAttr`, `formatPrice`, `formatDate`, `pluralize` |
| `common/js/nav.js` | Общий рендер навигационной панели: `renderSiteNav(current)` строит `nav.site-nav` (лого + «Категории»/«Мои заказы» + слот `#authNav`) и вызывает `renderAuthNav()`; `current = "categories" \| "orders"` или `""` |
| `common/css/base.css` | Базовые стили (навигация, контейнер, кнопки, формы) на всех страницах |
| `*/css/main.css` | Постраничные стили (`categories` / `catalog` / `checkout` / `orders`) |

Страницы связаны ссылками; данные передаются через URL-параметры и хранилище, не через состояние JS. Ссылки в страницах используют относительные пути уровня раздела (`../categories/...`, `../common/...`).

## Ключи localStorage

- `catalog_v1`: `{ [категория]: Item[] }`, `Item = { id?, name, type: "Товар"|"Услуга", price: number, desc?: string|null }`
- `cart_v1`: `[{ category, name, type, price, qty }]` — при совпадении категория+название количество суммируется; невалидные строки (позиция удалена) отбрасываются на лету
- `catalog_orders`: зеркало заказов

Заказ: `{ id, num, status, createdAt, updatedAt?, category ("Кат1 · Кат2"), itemName, lines[], total, comment: string|null, customer: { name, phone, email } }`. `id` — base36 timestamp; `num` = length(orders) + 1; при создании статус всегда `"new"`.

## Правила и валидация (соблюдать в новом коде и правках)

- Название категории/позиции: trim ≠ "", ≤ 80 символов. Категории уникальны без учёта регистра (добавление и переименование). Позиция при обновлении — уникальна в своей категории, регистр не важен.
- Тип позиции только «Товар» или «Услуга»; ввод нормализуется по совпадению без учёта регистра.
- Цена: число > 0 и ≤ 100 000 000, округляется до целого; парсер в `common/js/data.js` допускает пробелы/запятые (`"1 234"` → `1234`).
- Корзина: qty ∈ [1, 99].
- Форма заказа: имя ≥ 2 символов; телефон после удаления пробелов/скобок/дефисов подходит под `^\+?\d{10,15}$`; email опциональный (`type="email"`); чекбокс согласия на обработку ПДн обязателен.

## UI-конвенции

- Навигационная панель сверху на каждой странице рендерится общим модулем `common/js/nav.js`: `renderSiteNav(current)` в постраничном скрипте (первой строкой) — logo «Онлайн магазин» + пункты «Категории» и «Мои заказы»; активный пункт — `li.current` с `<span>` без активной ссылки (`current = "categories" | "orders"`), на остальных страницах — `""`. Новый пункт меню добавляется в `NAV_ITEMS` в `common/js/nav.js`; статичный HTML `nav.site-nav` в страницах больше не править.
- Все пользовательские строки экранировать при вставке в DOM (`escapeHtml`/`escapeAttr`) — не использовать `innerHTML` с сырыми данными.
- Цены: `toLocaleString("ru-RU") + " ₽"`.
- Русская плюрализация (товар/товара/товаров, заказ/заказа/заказов).
- Удаление категорий и позиций — подтверждение вторым кликом по кнопке (`✓` / class `.confirm`); у категорий автосброс кнопки через 2500 мс.
- Ошибки валидации показываются под формой; не бросать исключения наружу.

## Запуск

Сборки нет, Node-зависимостей и E2E-тестов в репозитории больше нет: открывать `categories/index.html` в браузере (рекомендован обычный таб, а не `file://`, чтобы корректно работало зеркало заказов). После правок JS на любой странице прогонять по минимуму вручную: категории → каталог позиции → «Заказать» → оформление заказа → заказ в списке → детали с переходом статусов.

## Примечания

- Seed: при отсутствии `catalog_v1` создаётся 44 позиции (11 категорий × 4), `common/js/data.js`.
- Страницы заказов (`orders/index.html`, `orders/order-detail.html`) читают заказы через `common/js/storage.js`; не читать `window.name` напрямую в других местах.
- Смена статуса разрешена только вперёд с `new → processing → done`; UI показывает одну кнопку перехода на странице деталей заказа.
- `orders/js/status.js` содержит общедоступные константы статусов (`STATUS_LABELS`, `ORDER_STATUS_FLOW`), но пока не подключён ни одной страницей — при правках статусного кода поднимать общий модуль, а не дублировать карты.
