# Системный анализ проекта «Онлайн магазин»

Статическое веб-приложение на vanilla HTML/CSS/JS (без сборки и фреймворков): каталог категорий → позиций (товары/услуги), покупательская корзина и заказы со статусами. Все данные живут только на клиенте (`localStorage` + `window.name`). Код разложен по подкаталогам (страница = каталог, общие модули — в `common/`); корень содержит только документы.

## 1. Технический стек

| Компонент | Технология |
|---|---|
| UI | Нативный HTML + ванильный JS (глобальные функции, `<script>` без модулей) |
| Стили | Чистый CSS: общий `common/css/base.css` + постраничные `*/css/main.css`. Адаптивность — 2 медиазапроса на 720px (`checkout`, `orders`) |
| Хранение | `localStorage` (каталог, корзина, зеркало заказов) + `window.name` (основное хранение заказов) |
| Тесты | см. §7 «Тестирование» |
| Сборка/сервер | Отсутствуют. Сайт открывается как `file://` или через любой статический хостинг (рекомендован обычный таб) |

## 2. Архитектура и модули

Классическая «страница = скрипт» архитектура: каждая HTML-страница подключает нужные JS-файлы в фиксированном порядке, состояние живёт в глобальных переменных/функциях (общий namespace без конфликтов).

Зависимости между модулями (направление — «использует»):

```
categories/index.html → common/data.js + common/utils.js        + js/script.js   | 167 стр.
catalog/index.html    → common/data.js + common/cart.js + utils  + js/main.js     | 197 стр.
checkout/index.html   → common/storage.js + data.js + cart.js + utils + js/main.js | 167 стр.
orders/index.html     → common/storage.js + common/utils.js      + js/orders.js   | 101 стр. (локальные копии `escapeHtml`/`formatPrice`/`formatDate`, своя карта статусов)
order-detail.html     → common/storage.js + common/utils.js      + js/order-detail.js | 139 стр.
```

| Модуль | Ответственность | Ключевые API |
|---|---|---|
| `common/js/data.js` (209 стр.) | Модель каталога: seed-данные, CRUD категорий и позиций, валидация (`normalizeItem`) | `getCategories`, `addCategory`, `renameCategory`, `removeCategory`, `addCategoryItem`, `updateCategoryItem`, `removeCategoryItem` |
| `common/js/cart.js` (74 стр.) | Корзина: агрегация по категории+название, qty 1–99, ленивое отсечение невалидных строк | `addToCart`, `setCartItemQty`, `removeCartItem`, `getCartLines`, `clearCart` |
| `common/js/storage.js` (59 стр.) | Заказы: инициализация из `window.name` → зеркало в `localStorage`, save/status/find | `loadOrders`, `saveOrder`, `setOrderStatus`, `findOrder` |
| `common/js/utils.js` (40 стр.) | Общие утилиты: экранирование, форматирование цен/дат, плюрализация | `escapeHtml`, `escapeAttr`, `formatPrice`, `formatDate`, `pluralize` |
| `common/js/nav.js` | Общий рендер навигационной панели: строит `nav.site-nav` (лого + пункты из `NAV_ITEMS` + слот `#authNav`) и вызывает `renderAuthNav()`; статичный HTML шапки в страницах удалён | `renderSiteNav(current)` — `"categories" \| "orders"` или `""`; `NAV_ITEMS` |
| `categories/js/script.js` (167 стр.) | Страница категорий: рендер, поиск, inline-переименование, удаление по второму клику | — (UI только) |
| `catalog/js/main.js` (198 стр.) | Каталог категории: сетка, фильтр по типу/поиск, форма позиции, «Заказать» → гость перенаправляется на `login/` (`requireAuthRedirect`), авторизованный — корзина + редирект на checkout через 350 мс | — |
| `checkout/js/main.js` (167 стр.) | Корзина-сводка со степперами, валидация формы покупателя, создание заказа, экран успеха | — |
| `orders/js/orders.js` (101 стр.) | Список заказов: поиск по тексту, фильтр по статусу, сводка «N заказов · сумма X»; сам содержит локальную копию `escapeHtml`/`formatPrice` и собственную карту статусов | — |
| `orders/js/order-detail.js` (139 стр.) | Детали заказа: состав позиций, покупатель, таймлайн, смена статуса new → processing → done (только вперёд; локальные копии утилит и собственной карты статусов) | — |
| `orders/js/status.js` (7 стр.) | Общие константы `STATUS_LABELS`, `ORDER_STATUS_FLOW`; пока не подключен ни на одной странице (см. §8, п. 10) | — |

## 3. Пользовательские сценарии и навигация

```
categories/index.html ───► catalog/index.html?category=... ──(Заказать: гость → login/; пользователь → корзина, 350 мс)──► checkout/index.html
        ▲                                                                      │ (подтверждение)
        │                                                                      ▼
orders/order-detail.html?id=... ◄── orders/index.html ◄──────────── success-экран («Мои заказы»)
   (таймлайн + смена статуса)
```

Особенности UX:
- Навигационная панель рендерится общим модулем `common/js/nav.js`; правила (`renderSiteNav(current)`, активный пункт, добавление пунктов в `NAV_ITEMS`) — в `AGENTS.md`, раздел «UI-конвенции». Специфика кода: внутренние переходы даны с `target="_top"`.
- Удаление категорий и позиций — подтверждение вторым кликом по той же кнопке (`✓` / `.confirm`); у категории автосброс через 2500 мс, **у позиции сброса нет** (см. §8, п. 1).
- Остальные UI-конвенции (экранирование, цены, плюрализация, ошибки под формой) — в `AGENTS.md`, раздел «UI-конвенции».
- Административное UI (форма добавления категории, кнопки «✎/×») рендерится только роли `admin` (`isAdmin()`, common/js/auth.js); форма на `categories/index.html` по умолчанию `hidden` в разметке, `refreshUiForRole()` включает её для админа. Гость на страницу не попадает — `requireAuthRedirect()` ведёт на `login/`.

## 4. Модель данных и хранилище

Ключи `localStorage`:

| Ключ | Формат |
|---|---|
| `catalog_v1` | `{ [категория]: Item[] }`, `Item = { id, name, type: "Товар"|"Услуга", price, desc? }`. При чтении — валидация структуры (`loadStoredCatalog`, common/js/data.js:72), при сбое seed заново |
| `cart_v1` | `[{ category, name, type, price, qty }]`; `type/price` перезаписываются из живого каталога при каждом чтении (`getCartLines`) — позиции из корзины, удалённые из каталога, отбрасываются на лету |
| `catalog_orders` | Зеркальный массив заказов (основное — `window.name`, префикс `orders::`, common/js/storage.js:1-26) |

Структура заказа — в `AGENTS.md`, раздел «Ключи localStorage». Специфично для анализа: `itemName` — название позиции (при одной строке) либо «N товаров»; `updatedAt` пишется при смене статуса.

Важно: заказы живут **в пределах одного контекста (вкладка/iframe)** — между вкладками синхронизации нет, зеркало в localStorage лишь страхует от утраты при `file://`. Лимит длины `window.name` (~2 МБ) теоретически ограничивает число заказов.

## 5. Валидация и ограничения

Полный перечень правил — в `AGENTS.md`, раздел «Правила и валидация»; README лишь ссылается на него. Особенности реализации, не вынесенные туда:
- парсер цены (`normalizeItem`) живёт в common/js/data.js, при этом HTML-поле цены в каталоге `type="number"`.

## 6. Безопасность

- Экранирование всех пользовательских строк перед вставкой в HTML — `escapeHtml`/`escapeAttr`. Реализация вынесена в общий модуль `common/js/utils.js`, но копии **дублируются** ещё в двух местах: локальные `escapeHtml`/`formatPrice` в `orders/js/orders.js:14-95+` и `orders/js/order-detail.js:35-135+` (подключаются после utils, затем затеняют общий). Рисков при подключении нет — поведение эквивалентно, но код дублируется.
- Нет передачи секретов/ключей; вся логика клиентская — «заказы» хранятся у того же пользователя (демо/прототипная модель, не многопользовательская система).
- PII: имя/телефон/email покупателя хранятся в localStorage без шифрования — приемлемо для прототипа, недопустимо для прода.

## 7. Тестирование

E2E-тесты (`test-crud.js`) и зависимость `puppeteer` удалены из репозитория; нет unit-тестов и lint/typecheck. Проверка изменений — ручная прогон по цепочке сценария (состав цепочки — в `AGENTS.md`, раздел «Запуск»). Легко тестируемые чистые функции (`normalizeItem`, плюрализация, storage) остаются без автотестов.

## 8. Детектированные проблемы и code smells

| # | Место | Проблема |
|---|---|---|
| 1 | `catalog/js/main.js:163-167` | Кнопка подтверждения удаления позиции — «Confirm?» (латиница), несогласованно с `✓` у категорий; отсутствует автосброс таймера, как в categories. `let confirmBtn = card.querySelector(...)` не используется. |
| 2 | `catalog/js/main.js:85` | `renderItemForm(allItems)` объявлена, но нигде не вызывается (используется `renderFormState`) — мёртвый код. |
| 3 | `orders/js/orders.js`, `order-detail.js` | Мёртвые ветки для «legacy» заказов с полями `o.qty`/`o.unitPrice`, которых в текущей схеме создания заказа нет (checkout создаёт только `lines[]`). |
| 4 | `common/js/utils.js:19-28` vs. локальные копии | `formatDate` в utils реализован через вспомогательный `dtoLocaleTimeStr`, тогда как в orders/order-detail локальные версии используют прямой вызов `toLocaleTimeString` — небольшие отличия дублированного кода (см. §6). |
| 5 | `categories/js/script.js:89` vs другие обработчики | Логика переименования может дублироваться между click по `.btn-submit` и submit формы; извлечение имени через `anchor.href.split("category=").pop()` хрупко при появлении подстроки `category=` в названии. |
| 6 | `common/js/data.js:3-70` | Seed-данные содержат множество некорректных/несуществующих русских слов («Леда для кошек нарезка», «Мавроматическая выдача порщия корма»,…) — автогенерация; как демо-контент вводит в заблуждение. |
| 7 | `checkout/js/main.js:125` | `id` заказа = base36 временной метки без случайного хвоста (в отличие от элементов каталога) — теоретическая коллизия при двух заказах за одну миллисекунду. |
| 8 | CSS | Адаптивность только на 720px, и только для `checkout`/`orders`; сетки продуктов (`catalog`) и карточек категорий на мелких экранах не оптимизированы отдельно. |
| 9 | Общие утилиты utils + локальные двойники (см. §6) + дубль карт статусов — нет единственного центра; при правке легко попасть в рассинхрон между страницами заказов и остальными. |
| 10 | `orders/js/status.js` объявлен как общий модуль констант (`STATUS_LABELS`, `ORDER_STATUS_FLOW`), но ни одна страница его не подключает — либо подключить и убрать дубли из orders/order-detail, либо удалить файл. |

## 9. Резюме и рекомендации

**Сильные стороны**: единая структура «страница = каталог + общие модули в common», строгая вынесенная валидация (`normalizeItem`), общий слой утилит (`common/js/utils.js`, `storage.js`, `cart.js`), защита от XSS, аккуратный UX (подтверждения, плюрализация, пустые состояния).

**Рекомендации по приоритету**:
1. Убрать дубли утилит из `orders/js/orders.js`/`order-detail.js` (использовать `common/js/utils.js`) и подключить `orders/js/status.js`, удалив локальные карты статусов из обоих скриптов заказа — либо удалить сам status.js.
2. Убрать мёртвый код (`renderItemForm`, legacy-ветки `o.qty`/`o.unitPrice`), унифицировать подтверждение удаления позиции с категорией (`✓` + автоотмена).
3. Пергенерировать seed-данные на осмысленном русском.
4. Добавить случайный suffix к id заказа (или принимать коллизии: один пользователь — одна вкладка/контекст).
