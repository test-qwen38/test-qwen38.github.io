# Онлайн магазин — каталог товаров и услуг с оформлением заказов

Статическое мультистраничное веб-приложение (vanilla HTML/CSS/JS, без сборки) для управления каталогом категорий → позиций (товары/услуги), корзины покупательской корзины и заказов со статусами. Все данные хранятся на стороне клиента: `localStorage` + перенос через `window.name`.

Код разложен по подкаталогам — один каталог на страницу, общие модули в `common/`; корень репозитория содержит только документы. Точка входа — `categories/index.html`.

## Сценарий пользователя

1. **Категории** (`categories/index.html`) — просмотр и поиск категорий; добавление/переименование/удаление категорий доступны только роли `admin` (гостю — вход).
2. **Каталог категории** (`catalog/index.html?category=...`) — сетка позиций; поиск по названию; фильтр по типу (Все / Товары / Услуги); добавление, редактирование и удаление позиций; кнопка «Заказать» кладёт позицию в корзину и через 350 мс ведёт на оформление.
3. **Оформление заказа** (`checkout/index.html`) — сводка корзины со степперами количества (1–99) и удалением позиций; форма покупателя (имя, телефон, email, комментарий, согласие на обработку ПДн); после подтверждения заказ сохраняется, корзина очищается, показывается экран успеха.
4. **Мои заказы** (`orders/index.html`) — список заказов (новые сверху), поиск по названию позиции/категории/покупателю, фильтр по статусу; сводка «Показано N заказов · на сумму X».
5. **Детали заказа** (`orders/order-detail.html?id=...`) — состав позиций с ценами, данные покупателя, комментарий, таймлайн и смена статуса: `new → processing → done`.

## Модель данных и хранилище

Ключи `localStorage`:

| Ключ | Содержимое |
|---|---|
| `catalog_v1` | `{ [категория]: Item[] }`, где `Item = { id?, name, type: "Товар"|"Услуга", price: number, desc?: string|null }` |
| `cart_v1` | `[{ category, name, type, price, qty }]` |
| `catalog_orders` | Зеркальный массив заказов (основное хранение — `window.name` с префиксом `orders::`) |

Заказы дублируются в `window.name`, чтобы переживать навигацию внутри iframe; при загрузке страницы сначала читается `window.name`, затем зеркало.

Структура заказа:

```js
{
  id,                      // base36 временной метки (Date.now().toString(36)) — создаётся в checkout/js/main.js
  num,                     // порядковый номер = длина массива заказов + 1
  status,                  // "new" | "processing" | "done", при создании всегда "new"
  createdAt,               // ISO-дата; updatedAt — при смене статуса
  category: "Кат1 · Кат2", // уникальные категории через « · »
  itemName,                // название позиции (при одной строке) либо «N товаров»
  lines: [{ name, type, category, price, qty }],
  total,                   // сумма по позициям
  comment: string | null,
  customer: { name, phone, email: string|null },
}
```

Статусы: `new` («Новый») → `processing` («В обработке») → `done` («Выполнен»); переходы возможны только вперёд, кнопка управления показывается на странице деталей заказа (`orders/order-detail.html`). Общие константы статусов — в `orders/js/status.js`.

## Seed-данные

При отсутствии `catalog_v1` каталог засевается данными из `SEEDED_CATALOG` (`common/js/data.js`) — 44 позиции (11 категорий × 4).

## Запуск

Статический сайт: достаточно открыть `categories/index.html` в браузере (сервер не требуется; для корректной работы зеркала заказов рекомендуется обычный таб, а не file://). Node-зависимостей и E2E-тестов в репозитории больше нет.
